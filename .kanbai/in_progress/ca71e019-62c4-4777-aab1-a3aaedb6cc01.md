## Summary
Agents working on a card frequently discover adjacent work that is out of scope for their current task but essential — bugs, missing features, tech debt, prerequisites. Today they either silently ignore these or mention them in a comment that gets lost. Instead, agents should be encouraged (via rules + tooling) to auto-create cards for discovered work and link them back.

## Problem
- Agent is implementing feature X, realizes Y is broken or missing
- Y is out of scope for the current card — agent shouldn'''t derail
- But if Y isn'''t captured, it'''s lost knowledge
- Currently no convention or tooling to support this pattern

## Implementation

### Agent rules (agent_rules.py)
Add explicit instruction block:

> **Discovered work**: When you encounter something that is out of scope for your current card but needs to be done (bugs, missing features, tech debt, prerequisites, edge cases), create a new card for it immediately using `create_card`. Then link it to your current card using `link_cards` with an appropriate type (`blocks`, `related_to`, etc.). Add a brief comment on your current card noting the discovery. Do NOT try to fix it inline — stay focused on your current card.

### New MCP convenience tool (server.py)
`discover_work(from_card_id, title, description, priority="medium", link_type="related_to", tags=[])`

Wraps: create_card + link_cards + add_card_comment in one atomic call:
1. Creates new card in backlog with the given fields
2. Inherits epic from the source card
3. Links new card to source card with the specified link_type
4. Auto-adds a comment on the source card: "Discovered related work: #{new_number} — {title}"
5. Auto-adds a system comment on the new card: "Discovered while working on #{source_number}"
6. Returns the new card

This reduces friction — one tool call instead of three, and the agent is more likely to actually do it.

### Discovery tags
- Auto-tag discovered cards with `discovered` tag for easy filtering
- UI could show a "Discovered" filter or badge on these cards
- Helps humans triage: "what did the agents find while working?"

### UI indicators
- In card dialog, show discovered cards in the links section with a lightbulb icon
- Board view: subtle indicator on cards that have discovered children
- Optional: "Discoveries" section in activity feed (#47)

### Link types to support
- `blocks`: discovered work blocks current card completion
- `related_to`: tangentially related, not blocking
- `prerequisite_for`: discovered work should be done before current card
- `follow_up`: should be done after current card is complete

### Health integration
- New signal: cards tagged `discovered` sitting in backlog for >5 days without triage
- Encourages humans to review agent discoveries promptly

## Example workflow
1. Agent picks up card #30: "Add search to table view"
2. While reading table_page.py, agent notices the column sort is broken for dates
3. Agent calls: `discover_work(from_card_id="#30", title="Fix date sorting in table view", description="...", priority="high", link_type="related_to", tags=["bug"])`
4. New card #31 created in backlog, linked to #30, tagged [bug, discovered]
5. Comment auto-added on #30: "Discovered related work: #31 — Fix date sorting in table view"
6. Agent continues working on #30 without derailing
