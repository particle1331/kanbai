Goal: make it impossible to send the same chat message twice in the chat UI (user sees duplicates).

What to do (very specific):
1) Add client-side dedup guard:
   - Generate a deterministic `dedupKey` per send attempt: SHA-256 of {conversationId, clientMessageId, normalizedText, trimmedAttachmentsMeta, timestampBucket}.
   - Store `dedupKey` in an in-memory map and also in sessionStorage for the current tab.
   - Before sending: if `dedupKey` already exists and not yet cleared, block sending and do NOT append to UI.
2) Add request idempotency:
   - Include header `Idempotency-Key: <dedupKey>` on every send request.
   - Ensure server treats repeated keys as the same operation and returns the same result.
3) UI state safety:
   - Disable the Send button until the request resolves (or times out).
   - Re-enable only if that exact request’s `dedupKey` completes/returns.
   - Ensure optimistic UI append happens exactly once per `dedupKey`.
4) Cleanup:
   - Remove `dedupKey` from storage/map on completion or error.

Acceptance criteria (must pass):
- Rapid double-click Send with same text produces exactly 1 outbound message and exactly 1 UI bubble.
- Network retry/timeouts do not create duplicates.
- Refresh during in-flight request does not duplicate on re-mount (uses idempotency).

Deliverables:
- Implement client + server idempotency.
- Add 3 automated tests: double-click, retry, and refresh/in-flight scenario.

Notes:
- Keep task size small (≤3 days). If too large, split into smaller cards: client guard, server idempotency, tests.
