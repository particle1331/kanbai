## Summary
Single MCP call that returns everything an agent needs to start working on a card. Replaces the current pattern of chaining 4-5 separate calls.

## Implementation

### MCP tool (server.py)
New tool: `get_card_context(card_id)` returns:

```json
{
  "card": {
    // full card fields: title, lane, priority, tags, due_date, etc.
    "description": "...",
    "checklist": [{"text": "...", "done": false}],
    "checklist_progress": "2/5",
    "file_refs": ["src/foo.py", "src/bar.py:10-30"]
  },
  "comments": {
    "instructions": [{"text": "...", "created_at": "..."}],
    "updates": [...],
    "decisions": [...],
    "blockers": [...],
    "notes": [...]
  },
  "linked_cards": [
    {"number": 12, "title": "...", "lane": "done", "link_type": "blocks"}
  ],
  "epic": {
    "name": "kanbai-dev",
    "description": "...",
    "recent_comments": [...]
  },
  "recent_activity": [
    {"timestamp": "...", "action": "moved", "detail": "backlog → in_progress"}
  ]
}
```

### Dependencies
- Builds on: typed comments (for grouping), checklists, file refs
- Can ship a v1 without those — just bundle existing card + comments + links + epic
- Enhance incrementally as other features land

### Agent rules
- Update agent instructions: "Use get_card_context to understand a card before starting work"
- Reduces token usage (one call vs many) and ensures agent has full picture

## Phased rollout
1. **v1 (no dependencies)**: card fields + flat comments + linked cards (title/lane) + epic description
2. **v2**: add grouped comments by role, checklist progress
3. **v3**: add file_refs, recent_activity from event_log

## Acceptance criteria
- [ ] MCP tool get_card_context returns bundled response
- [ ] Linked cards resolved with title + lane + link_type
- [ ] Epic context included (name, description)
- [ ] Agent rules updated to recommend this tool
- [ ] Response stays under reasonable token count (~2k tokens for typical card)
