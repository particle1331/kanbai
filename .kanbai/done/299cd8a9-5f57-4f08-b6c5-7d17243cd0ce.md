title: Escape stops working to close card after cancelling delete dialog
updated_at: '2026-06-21T16:11:19.212571+00:00'
---

After opening a card, clicking delete, then pressing Escape to cancel the delete confirmation dialog, pressing Escape no longer closes the card. The keyboard handler is not restored properly after the delete dialog is dismissed.

---
**Fixed 2026-06-22 00:11**
- **Understood:** The card dialog installs `_on_key` as the keyboard handler. When the delete dialog opened via `page.show_dialog()`, no new handler was set, so Escape triggered `_on_key` which called `_restore_kb()` — handing control back to the pre-card handler and breaking Escape for the card.
- **Encountered:** Needed to scope a separate keyboard handler to the delete dialog lifetime, same pattern as `_reset_context` in chat_panel.
- **Fixed:** `_delete()` now saves the current handler (`prev_kb`), installs `_on_delete_key` (Escape → cancel) on dialog open, and both cancel and confirm callbacks restore `prev_kb` before returning. Also replaced TextButton/TextButton with IconButton (CANCEL gray, DELETE_FOREVER red).
