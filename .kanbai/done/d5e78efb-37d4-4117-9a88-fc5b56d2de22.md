Attachments no longer work—investigate failure, reproduce, identify root cause, and implement fix.

## Root Cause (found & fixed)

**Flet 0.85 reference-count race in `ServiceRegistry.unregister_services()`.**

Flet 0.85 calls `ServiceRegistry.unregister_services()` after every event handler.  It keeps a service only if `sys.getrefcount(service) > 4`.  The `FilePicker` created inside `open_edit_dialog` had exactly **4** refs at the check point:

| Source | count |
|---|---|
| `_services` list slot | 1 |
| `for service in …` loop variable | 1 |
| `_pick_files` closure cell | 1 |
| `sys.getrefcount(…)` temp argument | 1 |
| **Total** | **4** |

`4 > 4` is `False` → the FilePicker was removed from the registry immediately after the dialog opened.  When the user clicked *Add files…*, `pick_files()` sent an invoke-method request to a control the frontend had already unmounted — silent failure.

## Fix (`src/kanbai/ui/card_dialog.py`)

Added `_picker_refs = [file_picker]` to hold one extra strong reference for the lifetime of the dialog, pushing the count to 5 (> 4 → kept).  `_cleanup_picker()` (called on every dialog-close path) clears the list so the service is released cleanly on close.  Also added the missing `_cleanup_picker()` call in `_open_linked`.
