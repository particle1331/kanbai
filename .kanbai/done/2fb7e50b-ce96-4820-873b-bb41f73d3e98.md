Investigate why the card delete button in the UI fails to delete cards (and confirm backend behavior). Identify failing request/handler and implement the fix so delete triggers proper archive (or permanent delete where supported).

---

## What Actually Happened (2026-06-22)

### Root Cause
The browser UI was served by a **uv tool install** of Kanbai (`~/.local/bin/kanbai` → `~/Library/Application Support/uv/tools/kanbai/`), not the local repo checkout. The local repo had the fix, but the running server did not.

MCP delete worked because it was called directly via the agent (which used the same process), while the browser UI was using the stale installed copy.

### Fix
- Reinstalled Kanbai from the repo using `uv tool install -e .` so the browser UI picks up local changes.
- In `card_dialog.py` `_confirm_delete`: added archive-then-delete fallback — tries `operations.delete_card()` directly, and if that fails (card not yet archived), auto-archives first then retries delete. Works for both archived and non-archived cards.
- Swapped the inline action-swap confirm (which replaced the card dialog's own buttons — confusing UX) for a **proper modal popup** with Cancel / Delete buttons and `Esc`/`Enter` keyboard support.
- Added icons to the confirm popup buttons (`CANCEL`, `DELETE_FOREVER`).
- Bonus: fixed `chat_mode` to be **session-only** (no longer persisted to `settings.json`), so it always resets to `agent` on restart instead of restoring a stale `yolo`.

### Failed Approach
- Initially suspected a `pi update` issue — ruled out; Pi and Kanbai are separate tools.
- Tried patching the installed uv tool site-packages directly — abandoned in favour of editable install.
- First delete fix used inline action-swapping (replacing dialog buttons in-place) — worked but poor UX; replaced with popup.
