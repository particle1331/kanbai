Done when agents automatically move a card to review when they finish task work and the transition is documented in the workflow.

## What was found

The MCP server `instructions` field (what external agents see on connect) only told agents *what lanes exist* but gave no guidance on when to use them. Agents had no explicit prompt to:
- move a card to `in_progress` when starting work
- move it to `review` when done (rather than straight to `done` or leaving it in `in_progress`)
- update the card description with a findings/fix summary for the reviewer

Kanbot (the embedded chat agent) is separate and only has board-management tools — no codebase access — so this change targets external MCP agents only.

## What was done (`src/kanbai/mcp_server/server.py`)

Added a **WORKFLOW DISCIPLINE** section to the `FastMCP` `instructions` string with three mandatory rules:

1. **PICK UP** — move the card to `in_progress` via `move_card` before starting any work.
2. **HAND OFF** — move the card to `review` when finished so the user can evaluate before closing.
3. **UPDATE DESCRIPTION** — before moving to `review`, update the card description with (a) what was found (root cause / analysis) and (b) what was done (fix / change), giving the reviewer full context without needing to read the diff or conversation history.

The instructions note that `backlog → in_progress → review` is the expected path for all agent-driven work.
