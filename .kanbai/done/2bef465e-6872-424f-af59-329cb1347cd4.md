## Problem

Agents currently get a flat description and unstructured comments. They lack:
- Progress tracking within a card (what'''s done, what'''s left)
- Structured decision records (why something was chosen)
- File/code references tied to specific cards
- Distinction between human instructions vs agent work logs

## Proposed Features

### 1. Typed comments (comment roles)
Give comments a `role` field: `instruction`, `update`, `decision`, `blocker`, `question`

- **instruction**: Human tells agent what to do ("implement X using approach Y")
- **update**: Agent reports progress ("completed step 2, moving to step 3")  
- **decision**: Records a choice made ("chose SQLite over Postgres because...")
- **blocker**: Flags something that needs human input
- **question**: Agent asks for clarification

MCP: add_card_comment(card_id, text, role="update")
UI: Color-coded comment bubbles, filter by role

### 2. Checklists / acceptance criteria
Structured subtasks within a card that agents can check off:

- Store as a list in frontmatter: `checklist: [{text: "...", done: false}]`
- MCP tools: `add_checklist_item(card_id, text)`, `toggle_checklist_item(card_id, index)`, `get_checklist(card_id)`
- Agents can report granular progress; health system can track completion %
- UI: Rendered as checkboxes in card dialog

### 3. File references (code pointers)
Link specific files/paths to a card so agents know what code is relevant:

- Store as `refs: ["src/kanbai/ui/board_view.py", "src/kanbai/board/health.py:46-80"]`
- MCP tools: `add_file_ref(card_id, path, line_range?)`, `get_file_refs(card_id)`
- When agent picks up a card, it immediately knows which files to read
- UI: Clickable file paths in card dialog (could open in editor via protocol handler)

### 4. Agent work log (auto-journaling)
Automatically append structured entries when agents interact with a card:

- When agent moves card: auto-comment "Moved to in_progress"
- When agent updates fields: auto-comment with diff summary  
- When agent adds file ref: auto-comment "Associated src/foo.py"
- Stored as comments with role=`system` (visually muted in UI)
- Gives full audit trail without agent needing to manually journal

### 5. Context bundle (get_card_context tool)
Single MCP call that returns everything an agent needs to start working:

- Card fields + description
- All comments (grouped by role)
- Checklist with completion state
- File references
- Linked cards (with their titles + statuses)
- Epic description + recent epic-level comments
- Recent activity on this card from event_log

This replaces the current pattern of: get_card → get_epic → list linked cards → ...

## Implementation Priority
1. Typed comments (small change, high leverage — agents can journal properly)
2. Checklists (structured progress tracking)
3. get_card_context bundle (agent QoL, no schema change)
4. File references (needs new field)
5. Auto work log (builds on typed comments)

## Notes
- All additions should be backward-compatible (new optional fields, new tools)
- Comments with roles still render as comments in markdown storage (just add a prefix or YAML tag)
- Checklists could use GitHub-style `- [ ] text` in the markdown body for portability
