Investigate why the card delete button in the UI fails to delete cards (and confirm backend behavior). Identify failing request/handler and implement the fix so delete triggers proper archive (or permanent delete where supported).

---
**Fixed 2026-06-22**
- **Understood:** `operations.delete_card()` requires a card to be archived before it can be permanently deleted (returns `False` otherwise). The UI delete button's `confirm` callback called `delete_card` directly without archiving first. For non-archived cards `ok` was always `False`, so the dialog silently closed and nothing happened — the card was never removed.
- **Encountered:** No backend changes needed; the backend behaviour (archive-then-delete) is intentional. The fix is purely in the UI confirm handler.
- **Fixed:** In `card_dialog.py` `_delete` → `confirm`, added a check: if `card.archived` is `False`, call `operations.archive_card(card_id)` first before calling `delete_card`. This makes the delete button work atomically for both archived and non-archived cards. Also suppressed a pre-existing Pyright `reportCallIssue` false-positive on the `_on_key_create` forward-pass of the keyboard handler (`type: ignore[call-arg]`).
