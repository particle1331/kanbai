## Summary
Add a `role` field to comments so agents and humans can categorize what a comment means. This is the foundation for structured agent communication.

## Roles
- **instruction** — Human tells agent what to do ("implement X using approach Y")
- **update** — Agent reports progress ("completed step 2, moving to step 3")
- **decision** — Records a choice made ("chose SQLite over Postgres because...")
- **blocker** — Flags something that needs human input before continuing
- **question** — Agent asks for clarification

## Implementation

### Storage (models.py / markdown_store.py)
- Add optional `role` field to comment dicts: `{id, text, created_at, author, role}`
- Default role: `note` (backward-compatible with existing comments)
- Markdown storage: prefix comment text with `[role]` tag, e.g. `<!-- role:decision -->`
- SQLite cache: add `role` column to comments if stored separately, or include in JSON blob

### MCP (server.py)
- Update `add_card_comment(card_id, text, role="note")` — new optional param
- Update `get_card()` response to include role in each comment
- Agents can filter: "show me all blockers" or "show me all instructions"

### UI (card_dialog.py)
- Color-coded comment bubbles by role:
  - instruction: blue (#58A6FF)
  - update: grey (#8B949E) 
  - decision: green (#56D364)
  - blocker: red (#F85149)
  - question: orange (#DB8132)
  - note: default grey
- Small role badge/icon on each comment
- Optional filter dropdown in comment section to show specific roles

### Agent rules (agent_rules.py)
- Update agent instructions to explain comment roles
- Recommend: use `update` when reporting progress, `decision` when making choices, `blocker` when stuck

## Acceptance criteria

- [ ] MCP add_card_comment accepts role param
- [ ] UI renders color-coded comments by role
- [ ] Existing comments without role default to "note"
