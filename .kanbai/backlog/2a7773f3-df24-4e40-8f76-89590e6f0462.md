## Overview

Pre-defined card structures (templates) for recurring task types — bug reports, features, spikes, chores. Reduces friction for both humans and agents creating well-structured cards.

## Plan

### Phase 1: Template definitions
- Store templates as markdown files in .kanbai/templates/ (e.g. bug.md, feature.md, spike.md)
- Template format: YAML frontmatter (default lane, priority, tags) + markdown body (description skeleton with placeholders)
- Ship 3-4 built-in templates; users can add custom ones

### Phase 2: UI integration
- "New Card" dialog gets a template picker dropdown (or grid of template cards)
- Selecting a template pre-fills title pattern, description skeleton, tags, priority
- User edits the pre-filled fields before saving

### Phase 3: MCP / agent integration
- New MCP tool: list_templates() — returns available templates with their structure
- Extend create_card to accept template parameter — agent says create_card(template="bug", title="...", ...) and gets the skeleton pre-filled
- Agents can create well-structured cards without knowing the format by heart

### Phase 4: Template management
- Settings dialog section to view/edit/delete templates
- CLI command: kanbai template list|create|edit

## Built-in templates (draft)

### Bug
- Tags: [bug]
- Priority: high
- Description skeleton:
  - **Steps to reproduce**
  - **Expected behavior**
  - **Actual behavior**  
  - **Environment**

### Feature
- Tags: [feature]
- Priority: medium
- Description skeleton:
  - **User story** (As a... I want... So that...)
  - **Acceptance criteria**
  - **Design notes**

### Spike
- Tags: [spike]
- Priority: medium
- Description skeleton:
  - **Question to answer**
  - **Time-box** (default: 2h)
  - **Findings** (filled after)
  - **Decision**

## Notes
- Templates are additive — they pre-fill but never restrict
- Keep templates simple markdown, not a DSL
- Agents benefit most: they can produce consistently structured cards
