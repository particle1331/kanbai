Investigate/implement a mechanism so the chat UI cannot send the same message twice (deduplicate on client + ensure server-side idempotency via message/request IDs). Add tests and a regression check for observed duplicate copies.

## What was found

Two independent race conditions allowed a single user submission to produce duplicate chat bubbles:

1. **Enter + Send-button race**: `on_submit` (Enter key) and `on_click` (Send button) both fired the same `_on_send` handler. With no atomic guard, both could read `self._busy == False` before either set it to `True`, spawning two `_do_send` threads and two identical bubbles.

2. **Double-submit / Enter+click combo**: Even with a single event source, rapid double-clicks or an Enter+click within milliseconds could both pass the busy check before the UI disabled the input.

## What was done (`src/kanbai/ui/chat_panel.py`)

- Added `self._send_lock = threading.Lock()` — `_on_send` now acquires the lock before checking/setting `self._busy`, making the check-and-set atomic so only one thread can ever proceed.
- Added `self._last_sent: tuple[str, float]` + `self._DEDUP_WINDOW = 1.5` seconds — identical text submitted within the window is silently dropped, covering double-click and Enter+click combos.
- Input field and Send button are disabled immediately inside the lock before the background thread is spawned, providing visual feedback and a third layer of protection.
