## Summary

Make the Kanbai app treat **each card as a 1:1 unit of PR work**.

- When a card is created (agent or human), open/identify its PR immediately.
- As work progresses, updates/commits are applied to the PR associated with that card.
- Health expectations (cycle-time thresholds) must be adjusted because PR-backed
  work tends to have longer “expected completion” windows.

## Problem / Motivation

Today:

- Agents can create discovered/related cards, but there is no consistent “work unit
  lifecycle” mapping to PRs.
- Health metrics (and the written health model) assume shorter cycle-time
  expectations.

Once each card corresponds to a PR:

- The expectation window should increase from roughly **1–3 days** to about
  **3–5 days**.
- The **health doc + thresholds** (and any chart annotations) must be updated to
  reflect the new expectation bands.

## Proposed approaches

### Option A — Parent PR, child commits

- If a card has a **parent**:
  - The **parent** card gets the PR.
  - Each child task updates/commits against the **parent PR**.
- If a card has **no parent**:
  - That card is a root → **it gets its own PR**.

### Option B — Tag PR sources

- Introduce a tag like `pr_source` (or similar).
- A card tagged as a PR source causes the PR to be opened **before** any
  dependent/task child work begins.
- Children link back to the PR source card for routing.

### Option C — Use task counts for dynamic thresholds

- If PR-backed work is structured into N tasks/children, health thresholds
  should be adjusted based on task count (e.g. allow longer cycle time for
  multi-task PRs).
- This reduces over-penalizing correctly-scoped PRs.

## Implementation checklist (card-owned scope)

1. **Card metadata for PR mapping**
   - Add a durable field to associate a card with a PR (ID/URL/state).
   - Record **creator** metadata so we can distinguish:
     - creator is an agent vs human/user
     - creator identity (name / agent handle)

2. **Agent workflow integration**
   - When an agent creates a discovered card, ensure the creator metadata is
     set and the PR routing rules apply immediately.

3. **Health model updates**
   - Update `board/health_doc.py` to describe the new expectation window (3–5 days).
   - Update the underlying cycle-time thresholds in `board/settings.py` so the
     Health page charts and verdicts match the doc.

4. **UI / observability**
   - Surface PR association in the card dialog and (where helpful) on the board
     tile.
   - Ensure health dashboards continue to work as before, but with updated
     threshold lines/labels.

## Acceptance criteria

- [ ] There is a clear, durable mapping from card → PR.
- [ ] Agent-created cards correctly populate creator metadata (agent vs user).
- [ ] Cycle-time thresholds and written health doc update to the new expectation
      window (~3–5 days).
- [ ] Health charts/threshold annotations match the updated thresholds.
